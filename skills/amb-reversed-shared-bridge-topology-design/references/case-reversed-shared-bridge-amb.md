# Case study: 5-DOF AMB reversed shared bridge (RSB) topology and current loop

Reference model: `model/Reversed_shared_Bridge_with_RL_load.slx` (md5 `80211c88ec9d55c4f5af97db1d07eff0`) with its
parameters at `model/parameters_for_AMB_topology.m` (md5 `a90c6e390a9c1e14bf015396b2d6054d`), verified with
**MATLAB 25.2 (R2025b), Simulink 25.2, Simscape 25.2, Simscape Electrical 25.2 (Linux `glnxa64`)**.

Everything below is measured from that model; the block names and parameter values are listed in
`references/block-and-parameter-map.md` and re-checked by `scripts/verify_model_facts.m`. The numbers are
regenerated by `scripts/run_case_study.m`, which also regresses them against the values quoted here.

## 2. Derivations verified against the model

### 2.1 Unidirectional winding current

Each module leg is one controlled switch plus one freewheel diode pointing the same way, and the
Simscape IGBT block is configured with `diode_param = external` (no internal antiparallel diode).
Therefore:

- T module: current X -> Shared only (the switch feeds X from P, the diode feeds X from N; nothing can
  pull X above P or below N);
- B module: current Shared -> Y only.

Measured over the whole 0.1 s run: the minimum of all ten winding currents is exactly 0 (at t = 0) and no
device ever carries reverse current - the four device classes (module IGBT, module diode, shared-leg
IGBTs, shared-leg diodes) all show a minimum of 0 A.

### 2.2 Winding voltage law

With `d` the duty of the module's own switch and `d_sh` the effective duty of the "shared node at P"
state:

```
T module :  V = U_dc*(d - d_sh)
B module :  V = U_dc*(d + d_sh - 1)
```

Both reduce to `V = U_dc*u` with the modulation of section 2.3. In steady state `V = R*i` (the inductor
carries no DC voltage), which is how `d_sh` can be inferred from measured duties and currents.

### 2.3 Modulation law

```
u_eff = [+u for T modules, -u for B modules]
m     = 0.5*(max(u_eff) + min(u_eff))
b_i   = 0.5 - m + u_eff,i      (winding i threshold)
b_sh  = 0.5 - m                (shared-leg threshold)
```

and the gate polarity of section 1.9 of the skill. Measured agreement in steady state:

| Quantity | Predicted | Measured |
|---|---|---|
| `m` | 0.020810 | (computed from the logged commands) |
| `b_sh` (tag `sw0`) | 0.479190 | **0.479190** |
| winding thresholds | 0.5348279 / 0.5291596 / ... / 0.4651721 | **identical to 1e-8** |

### 2.4 Voltage budget

The controller output is not just `R*i/U_dc`: the dead time of the shared leg and the device drops
also have to be compensated, and the two contributions can be separated with the measured effective
shared-node duty (0.50081 against a command of 0.47919, i.e. +0.02162 p.u. = +4.3 V on the shared node):

| Term | T module (`i_a1` = 5.5108 A) | B module (`i_a4` = 5.4886 A) |
|---|---|---|
| controller output `u` | +0.0556375 | +0.0140183 |
| `R*i/U_dc` | +0.0275540 | +0.0274430 |
| dead-time offset on the shared node | +0.0216200 (reduces `V`) | -0.0216200 (raises `V`) |
| device drops (IGBT + diode) | +0.0064600 (1.29 V) | +0.0081953 (1.64 V) |
| sum | 0.0556340 vs 0.0556375 | 0.0140183 vs 0.0140183 |

The same dead-time offset therefore appears with **opposite sign** in the two module types - it is not a
common-mode error, which is why both module types need slightly different command levels for the same
winding current.

### 2.5 Shared-leg current law

`I_sh(into node) = sum_T i - sum_B i = 2*bias*(p - q) + sum_split (+-i_ref,k)`. With
`(p,q,s) = (2,2,1)` the bias terms cancel and only the split pair's control current is left, which is
exactly what the measurements show (section 3.4).

## 4. The three debugging rounds and what each taught

The model was built and verified in three rounds. The power stage was **bit-identical** throughout; only
the control/filter/solver-facing parts changed. The differences are the most transferable result of this
case study.

### 4.1 v1 - the defects

- **Feedback sampling.** A single sample per carrier period at `t = k*Ts` biased the regulated
  average by +/-0.9 % (measured +0.0486 A on `i_a1`, -0.0501 A on `i_c3`). Same-type pairs cancelled
  the bias in their difference; the split pair added it and showed a **-9.87 % control-current error**
  (0.9013 A instead of 1.0 A) and a 0.4514 A p-p differential ripple against 0.0605 A for the other
  pairs.
- **Min/max implementation.** `MinMax` blocks chattered on equal command inputs; with `i_ref = 0` the
  run aborted at 79.6 us with "1000 consecutive zero crossings".
- Dead time was 2 us, StopTime 0.025 s, and the shared-leg current had to be reconstructed from the ten
  winding currents (no sensor).

### 4.2 v2 - the fixes and one regression

Applied: 4-sample averaging at 80 kHz (bias 0.9 % -> **0.2 %**, split pair -9.9 % -> **+2.2 %**),
sort-based min/max (`i_ref = 0` now completes with all ten currents at 4.9997 A), dead time 2 us -> 1 us,
StopTime 0.1 s, and two shared-leg current sensors. Step count per millisecond nearly halved.
Regression: the start-up overshoot grew to **+24...+27 %** (`i_a1` peak 6.836 A at 187.6 us), because the
feedback chain of that version still contained a 6 kHz second-order low-pass whose lag the averaging had
made unnecessary.

### 4.3 v3 - the simplification

Removed the feedback low-pass. Measured effect:

| Metric | v2 (with low-pass) | v3 (removed) |
|---|---|---|
| steady-state currents / errors | 5.5108 / 4.4886 A, +0.196 / -0.253 % | **identical** |
| 4-sample averaging bias | -0.0108 A | **identical** |
| start-up peak `i_a1` / `i_a4` | 6.836 A (+24.3 %) / 7.010 A (+27.5 %) | **5.566 A (+1.2 %) / 5.708 A (+3.8 %)** |
| 63 % rise time | 65 us | 86 us |
| major steps / wall time | 1 352 399 / 58.4 s | **1 136 652 / 37.0 s** |
| shared-leg current (steady / start-up peak) | 1.111 A / 6.487 A | identical |

The lesson: **once the feedback is oversampled and averaged, a low-pass in the feedback path is
redundant; keeping it costs phase margin and shows up as start-up overshoot.**

## 5. Reproduction

`scripts/run_case_study.m` reproduces every number above from the bundled model. It

1. locates the model and its parameter script relative to its own folder (the skill folder can be copied
   anywhere),
2. copies the model to the system temp folder and instruments the copy (marks the ten winding currents,
   the eleven gate commands, the two shared-leg currents and the ten controller outputs for logging),
   so the bundled asset is never modified,
3. run A: 0.1 s, steady state, pairs, duty law, feedback-averaging A/B, shared-leg statistics,
   start-up, ripple spectrum,
4. run B: 2 ms with `SimscapeLogType = 'all'` and `SimscapeLogLimitData = 'off'` for the device-level dead
   time, node duty and device currents,
5. run C: `i_ref = 0` for 30 ms (the degenerate case that used to abort),
6. run D: a 0.1 ms probe with `AlgebraicLoopMsg = 'error'`,
7. regresses every metric against the values in this document and prints one line per check, ending with
   `ALL CHECKS PASSED`.

All statistics are time-weighted (`sum(x.*dt)/sum(dt)`); the script prints the sample-mean value next to the
time-weighted one for the shared-leg current so the difference is visible (about 12x in an early version).

`scripts/verify_model_facts.m` independently asserts every block name, library path, parameter value,
port name, Goto/From tag and workspace variable listed in `references/block-and-parameter-map.md`.

## 6. Conclusions

1. **The topology works as intended.** Ten winding currents are regulated independently through one
   shared leg plus ten independent legs; the modulation law holds to 1e-8; the winding currents are
   unidirectional; there is no shoot-through and no algebraic loop.
2. **The reversal does what it promises.** The shared leg carries the algebraic sum of the control
   currents (1.111 A mean at `i_ref` = 1 A) instead of the sum of all winding currents (50 A), i.e. a
   45x reduction in mean stress, and the current scales with `i_ref` rather than with the bias - proven
   by the `i_ref` sweep including the `i_ref = 0` case where it falls to zero while 50 A still flows in the
   windings.
3. **Two implementation details dominate the accuracy**, and neither is a power-stage effect: the
   feedback sampling scheme (0.2 % vs 0.9 % steady-state error, and the split pair's control-current
   error) and the min/max realisation of the common-mode injection (a hard abort at `i_ref = 0` if
   implemented with `MinMax`).
4. **A split pair is expensive**; it inherits 9x the differential ripple and the un-cancelled
   common-mode error. Put the least accuracy-critical DOF there, or use an even number of pairs.
5. **What is deliberately not modelled** (device drops, thermal, magnetics, motion, bus dynamics,
   protection, quantisation) does not affect any of the conclusions above; it becomes relevant only in
   the next stage, together with bandwidth calibration, which must start from the fixed feedback chain of
   section 3.1 of the skill.
